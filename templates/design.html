design

4orm should feel direct, familiar, and a little handmade. These are the restrictions that keep the shared interface consistent without sanding down anyone's personal page.

the restrictions

content before chrome

Use plain structure, short labels, and visible controls. Decoration never carries meaning.

borders before shadows

Panels are white with a solid black border. Controls keep their inset and outset edges.

square by default

No soft cards, floating pills, glass, gradients, or ornamental corner radii.

one loud accent

Cyan identifies the shared shell. Semantic colors appear only when the state needs them.

the web stays recognizable

Links look like links, buttons look pressable, and forms keep persistent labels.

personal pages stay personal

Application helpers use a fourm- prefix. Never claim a generic class a member may use.

colour

The palette is small on purpose. Do not invent nearby shades for one screen.

success confirms that something finished.

error says what failed near the affected control.

notice asks for attention without implying failure.

type

Verdana leads, with Tahoma and Arial as local fallbacks. There are no downloaded fonts.

page heading

section heading

small heading

Body copy stays readable at the browser's normal size and a 1.45 line height.

Secondary copy is smaller and quieter, but still has useful contrast.

code and machine values use the browser monospace stack

controls

Use words before icons. A control owns its foreground, background, border, hover, focus, and disabled states.

ordinary link

structure

shared screens

A 920px wrapper, simple vertical rhythm, and panels only where a border clarifies grouping.

actions

Related actions share one wrapping row. A form does not force the next action onto a new line.

narrow screens

Layouts collapse naturally. Nothing depends on hover, fixed widths, or horizontal clipping.

member content

Custom HTML, CSS, and layouts may ignore this entire page. That freedom is part of the system.

the boundary

4orm owns: navigation, authentication, settings, administration, shared forms, and system feedback.

members own: profiles, pages, cards, embedded media, and their chosen visual voice.

When shared CSS needs a helper, scope it beneath .fourm-shell and name it .fourm-*.
